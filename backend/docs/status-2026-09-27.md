```

```

`backend/scripts/start_server.ps1` exists and is the documented-correct path. It resolves an

### 2.3 Known footguns (do not re-derive these)

| # | Footgun | Detail |
|---|---|---|
| 1 | **Selector event-loop factory is mandatory** | psycopg async cannot run on Windows' `ProactorEventLoop`. `run.py:28` passes `loop="app.core.eventloop:selector_loop_factory"` to `uvicorn.run`. uvicorn 0.36+ **no longer uses the event-loop policy** — it asks for a *factory* — so `set_event_loop_policy` alone is not enough. Omitting the factory silently yields a Proactor loop when reload is off. |
| 2 | **The factory must be zero-arg** | For a custom `loop=` string, uvicorn hands `import_from_string(value)` straight to `asyncio.run(loop_factory=...)`. A factory-*of*-factory produces a class where a loop instance is expected. See the docstring at `app/core/eventloop.py:36-43`. |
| 3 | **`RELOAD=false` is required** | `backend/.env` has `RELOAD=false`. V1 runs ingestion in-process (no worker queue), so a reload-triggered restart cancels the in-flight task. `start_server.ps1` throws if `RELOAD` is not `false`. |
| 4 | **`Start-Process` working-directory trap** | `cd backend` then `Start-Process … run.py` does **not** work — `Start-Process` does not inherit the caller's cwd, so `run.py` resolves to nothing, the process dies before binding, and you get a bare stderr line and no listener. Always pass an absolute `-WorkingDirectory`. |
| 5 | **`Start-Process -Redirect*` deadlocks the caller** | With a redirect, `Start-Process` switches to `CreateProcess(bInheritHandles=TRUE)`, duplicating the harness's output pipes into a long-lived detached server; the calling tool call blocks forever even though the script exits 0. The script deliberately uses `cmd /c` with redirection *inside* the child and no `-Redirect*`. |
| 6 | **`run.py` hardcodes `port=8000`** | `start_server.ps1` greps `run.py` and throws if its `-Port` disagrees, so the probe cannot target a port nothing is listening on while skipping the real one. Change both together. |
| 7 | **`copied .env.example will not boot** | `ollama_model` is `Field(min_length=1)` with **no default** (`app/core/config.py:86`), but `.env.example` never defines `OLLAMA_MODEL` or `OLLAMA_BASE_URL`. A fresh clone following `.env.example`'s own instructions fails settings validation at import. |
| 8 | **`uvicorn.out.log` / `uvicorn.err.log` in `backend/` are stale** | They are from a boot at 13:19:46 and are not the current server's output. Live logs are `%TEMP%\rag_policy_logs\server.out.log`. Both are gitignored (`*.log`). |
| 9 | **Container entrypoint bypasses `run.py`** | `backend/Dockerfile:19` runs `uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload`, i.e. neither the loop factory nor the `reload_excludes` are applied. Harmless on Linux (selector loop is the default there) but it is a different code path from the dev workflow. |
| 10 | **compose frontend Dockerfile name mismatch** | `docker-compose.yml:75` says `dockerfile: Dockerfile`; the file on disk is `frontend/dockerfile` (lowercase). `backend/Dockerfile` *is* correctly cased. The frontend build would fail on a case-sensitive filesystem. |

decided by the gate, not generated). Persistence is split into two short transactions: the
conversation + user question commit *before* the stream, the assistant message + citations
commit *after* — so no transaction is held open across generation, and a mid-generation
failure still leaves the question in history.

### 7.2 Fixed earlier — worth remembering (verified still in place this session)
